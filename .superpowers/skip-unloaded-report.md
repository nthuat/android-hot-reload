# Skip-unloaded-classes fix — report

Commit: `c631aa0` on `main`, pushed to `origin/main` (`98c209a..c631aa0`).

## What changed

- `agent/src/main/cpp/agent.cpp`: `HandleLoadDex` resolves each `LOAD_DEX` record
  independently. A class not currently loaded is collected into a `skipped` list instead of
  failing the batch. `RedefineClasses(n, defs)` is called once for whatever *did* resolve.
  Zero resolved → `kStatusOk`, "nothing redefined" detail, runtime NOT notified. ≥1 resolved →
  `kStatusOk`, redefine + notify as before, with a `| skipped N: ...` segment before the
  `| tierN` suffix. A real `RedefineClasses` rejection is still `kStatusFail`. Global refs are
  freed exactly once, same as before.
- `cli/.../Protocol.kt`: documented the exact `detail` format byte-for-byte.
- `cli/.../ReloadOrchestrator.kt`: `CycleOutcome.Reloaded` gained a `skipped: List<String>`
  field; new pure top-level `parseTier`/`parseSkippedDescriptors` functions parse the reply.
- `cli/.../Main.kt`: prints a `⚠ skipped ...` line after a normal reload, or a distinct
  `· nothing applied ...` line when everything was skipped. Exit code stays 0 both ways.
- `README.md` / `docs/superpowers/specs/2026-08-01-android-hot-reload-design.md`: documented
  the new skip-unloaded semantics.
