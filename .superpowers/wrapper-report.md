# `hotreload` wrapper script — report

## What shipped

**`gradle-plugin/src/main/kotlin/dev/thuat/hotreload/gradle/HotReloadWrapperScript.kt`** (new) —
pure content generator + file-write/clobber-guard, no network I/O, unit-testable against a plain
temp dir:
- `content(projectDir, applicationId, pluginVersion)` — builds the `hotreload` script text.
- `MARKER` — the unique comment line (right after the shebang) that identifies a script this task
  generated.
- `isOwnFile(existingContent)` — pure marker check.
- `writeTo(projectDir, applicationId, pluginVersion)` — writes/chmods the file, throwing
  `GradleException` if a file already exists at that path with no marker (the clobber guard).

**`InstallCliTask.kt`** — after installing/skipping the CLI download, calls
`HotReloadWrapperScript.writeTo(...)` and replaced the old long "ready. Run: \<full command\>"
output with a 2-line message pointing at `./hotreload` and calling out that it belongs in
`.gitignore` (machine-specific absolute paths baked in).

**Generated `hotreload` script** (root of whatever project runs `hotReloadInstallCli`):
```sh
#!/bin/sh
# Generated by hotReloadInstallCli -- DO NOT EDIT, this file is regenerated on every run.
# Plugin version: 0.1.5
#
# Thin wrapper around the CLI hotReloadInstallCli downloaded, with --project/--package
# baked in so day-to-day use needs no flags:
#   ./hotreload run                       # watch mode
#   ./hotreload bootstrap                  # re-attach after the app restarts
#   ./hotreload cycle --file path/to/File.kt
# Flags you pass win over the baked-in --project/--package (they come after on the
# command line, and the CLI keeps the last occurrence of a repeated flag), e.g.:
#   ./hotreload run --serial emulator-5554
#
# This file has machine-specific absolute paths -- add it to .gitignore.
set -e
script_dir=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)
cmd="$1"
if [ "$#" -gt 0 ]; then shift; fi
exec "$script_dir/build/hotreload/cli/bin/cli" "$cmd" --project "<abs project dir>" --package "<applicationId>" "$@"
```
Shebang stays line 1 (chmod +x, directly executable). `$script_dir` (not `$PWD`) locates the CLI
binary so `./hotreload` works from any cwd, or via an absolute/symlinked invocation.

**Override precedence, investigated**: the CLI's arg parser (`cli/.../Main.kt`) does
`args.drop(1).chunked(2).mapNotNull{...}.toMap()` — Kotlin's `Iterable<Pair<K,V>>.toMap()` builds
a map by inserting pairs in order, so a **later** occurrence of a key overwrites an earlier one:
**last flag wins**. The wrapper places the baked-in `--project`/`--package` *before* `"$@"` on the
exec line, so anything the caller passes — including re-passing `--project` or `--package`
explicitly — lands after and wins. Verified live (see below): `--package definitely.not.installed`
appended by the caller produced an error naming that bogus package, proving the override actually
took effect rather than being shadowed.

**README** — quickstart step 2 now says `hotReloadInstallCli` also generates `./hotreload` (with
a `.gitignore` mention), step 3 replaced with `./hotreload run`, plus a one-line note in the CLI
details section that `./build/hotreload/cli/bin/cli` still works directly if you'd rather skip the
wrapper.

## Tests

`gradle-plugin/src/test/kotlin/dev/thuat/hotreload/gradle/HotReloadWrapperScriptTest.kt` (new, 11
cases, all pass): shebang on line 1, marker present, plugin version present, exec line references
`script_dir/build/hotreload/cli/bin/cli` and `dirname -- "$0"`, `--project` then `--package` then
`"$@"` in that order on the exec line (the override-precedence contract), blank `applicationId`
falls back to a placeholder, `"$@"` passthrough present, `isOwnFile` true only for our own
content, `writeTo` creates+chmods a new file, `writeTo` overwrites its own prior file, `writeTo`
refuses (throws `GradleException`, leaves the file untouched) when a pre-existing file has no
marker. Existing suite (`CliInstallSupportTest`, `HotReloadPluginCoordinatorTest`, etc.) untouched
and still green.

  root isn't itself a wrapper-generating consumer project (`sample/` is, and `sample/` isn't where
  `hotReloadInstallCli` writes the wrapper either — it always lands on the root of whichever build
  invoked the task, which for this repo's own dev loop is `android-hot-reload/`, not `sample/`).
  Per requirement 5, this is intentionally left to consumers' own `.gitignore`, called out in both
  the task's console output and the README instead.
- No CLI (`Main.kt`) changes — the last-occurrence-wins behavior already gave the override
  semantics needed; only the wrapper's flag *ordering* mattered.
